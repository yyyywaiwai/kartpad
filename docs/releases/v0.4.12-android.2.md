# KartPad Android 0.4.12-android.2 — fullscreen fix and renderer diagnostics beta

**For ARM64 Android phones and tablets, Android 9/API 28 or newer, with Vulkan.**
This is version code 23, using the existing public release signer. It updates
the public Android APK in place. It is not an iPhone/iPad IPA, Mac app or tvOS
build, and it is not a verified fix for graphics corruption or frame drops.

## Changes

- Fix Android system bars remaining visible during gameplay (#119). Bars hide
  on entry and when game focus returns; edge swipes can still reveal them
  temporarily. The game menu keeps its safe margins.
- The game chooser has an optional **Renderer Validation** mode, off by default.
  It enables WebGPU validation and buffer bounds protection in the actual game
  renderer. The mode applies before the GPU device is created and is recorded
  in startup logs and health samples. Normal mode retains the previous release
  toggles. This checks a different path from the standalone Renderer Check app.
- **Export Private Diagnostics…** includes `process-exits.json`: up to eight
  Android exit records for KartPad. It distinguishes OS-reported native/Java
  crashes, low-memory exits, unresponsive processes and manual stops where the
  OS supplies that information. Android 11/API 30+ is required for exit history;
  older Android versions report it unavailable without blocking play.
- New processes label their build and last selected game for later exit
  attribution. Older/unrecognized records have null build/profile fields.
  System trace files, descriptions and other apps' histories are not copied.

The profile-aware save picker and checked disc-import fixes from android.1
remain included. Raw-save transfer still omits Retro's `RRRating.pul` and the
Mii database; it is not a complete Retro migration. Existing saves, identities
and game data are preserved. Never uninstall or clear storage to update.

## Targeted test

For #119, open Original or Retro, open/close the game menu, then go Home and
return. Confirm the notification/navigation bars hide during play and can
still be shown temporarily by an edge swipe. Renderer Validation can stay Off.

For graphics reports (#102/#104/#120):

1. Keep a save backup and install this APK over the existing public build.
2. Reproduce the affected character-selection/race scene with validation **Off**
   at the same resolution and aspect used for your comparison. Keep other
   settings unchanged.
3. Fully close KartPad, reopen the chooser, tap **Renderer Validation: Off** and
   **Enable**, then repeat that scene. Note whether the corruption changes or
   the app closes. Validation can reduce performance; this is not an FPS benchmark.
4. Fully close/reopen to the chooser and use **Export Private Diagnostics… →
   Save Locally…**. Review the archive locally. Share only relevant renderer
   validation warnings/errors and the matching exit entry, if present. Do not
   post the raw archive, game files, saves or personal identifiers.
5. Turn validation **Off** in the chooser before normal play.

Exit timestamps use Unix epoch milliseconds; runtime/health intervals use time
since boot. Exit history can be incomplete, and manually closing the app can
add a user-requested exit. No exit record is not proof that the game did not
crash. Memory values are the last OS samples, not peak use.

## Acceptance boundary

Host tests verify bounded, allowlisted exit metadata, old-Android behavior and
unavailable APIs, plus normal/diagnostic Dawn toggles in debug and release.
An isolated API 36 emulator verifies a real OS force-stop record surviving
restart with correct build/profile attribution and production ZIP export.
The bundle-derived, non-debuggable release passes Original startup/rendering
with validation off and on, universal and split APK installation, and durable
test-data preservation. Startup logs and health samples confirm the selected
renderer mode. The setting is atomically stored and re-read across chooser/game
processes. Release-emulator visual checks verify immersive entry, menu return,
Home/resume and transient edge swipes. All 140 Python tests, focused save/identity
tests and Android release lint pass.
Physical Adreno testing remains pending. This beta does not establish a fix
for #102/#104, sustained performance, or iPad external-display support.

Download the APK, companion notices ZIP and `SHA256SUMS` together. No owned
game assets, private logs, saves or signing material are included. The AAB
remains local. Private previews with a different signer need a separate,
backed-up migration; do not uninstall them to force this update through.
