# KartPad 0.5.0: fixes, evidence and release readiness

Updated September 20, 2026. **Published as the latest stable [v0.5.0 release](https://github.com/chrissotraidis/kartpad/releases/tag/v0.5.0).**
This records the release evidence; dated records retain the detailed investigation.
Older passing builds do not establish acceptance of newer binaries.

**Code134 was rejected for black vehicle thumbnails.** Two shader/copy defects
are reproduced and corrected in code135/build59. First-entry Retro Rewind
vehicle thumbnails pass on the owner Pixel. The owner subsequently confirmed
that code135 appears to fix the reported regression. This clears that reported
blocker; it does not record a separate full-race or all-mode endurance test. See the
[thumbnail investigation](../artifacts/2026-09-19/android-black-vehicle-thumbnails.md).

## Retro Rewind licenses and menu performance

The owner's first license still reports console-serial mismatch; the second
reaches versus worldwide. **This is recorded as unresolved, not fixed.**

The exact message is RWFC error **22005**. The service compares a profile's
registered serial list against the supplied console serial. Primary source:
[message definition](https://github.com/Retro-Rewind-Team/wfc-server/blob/a41eb097487b15fba55e063fe49c5eb88e4ab9a2/gpcm/error_messages.go#L1304),
[profile check](https://github.com/Retro-Rewind-Team/wfc-server/blob/a41eb097487b15fba55e063fe49c5eb88e4ab9a2/database/login.go#L42).
This describes upstream behavior; the live service's stored registration and
configuration are not available here.

The iPad's ConsoleIdentity.txt is byte-identical across the pre-update build42
backup, the pre-build58 backup and the current device readback. The earlier
[migration validation](../source-maintenance/VALIDATION.md) already reproduced
this old-license failure on both build41 and build42 while a new license logged
in. The #94 numeric serial ABI correction shipped earlier and is retained; it
is not a new 0.5.0 fix. A historical profile registration mismatch is therefore
supported by the evidence, but its stored expected identity is unknown. The
problem can follow a profile across platforms; this does not establish a new
serial-generation regression in every build. No license deletion, identity
rotation or server-side change was made. Both licenses remain intact.

Menu performance remains open. The captured Retro session at 4x resolution has
62 frame samples, ranging from 36.776 to 60.916 presentation FPS, including one
sample below 50 with no pipelines queued. This is not a controlled menu/race
benchmark and does not identify the cause. Successful login is not full online
race/results/reconnect acceptance.

## What is not being claimed fixed

- Samsung/S24 corruption (#193 and related reports), newer Red Magic report
  #308, and other unreplicated device-specific geometry failures.
- PowerVR capability rejection (#304); no unsupported GPU limits were relaxed.
- Warmed slow-device performance (#198/#275), Retro menu pacing, and universal
  faster gameplay.
- Mac Wii Remote/Classic Pro delay/remapping complaints (#306), all lifecycle
  input reports, and Original ghost discovery (#295).
- All crashes, full online endurance, or complete compatibility on untested
  hardware. Source similarity alone is not grounds to close an issue.

## Publication and follow-up

PR #307 is merged into main. The coordinated APK, unsigned IPA, Mac ZIP,
source archive, notices and checksum file are published together as v0.5.0.
All six GitHub downloads match their local SHA-256 values, and their public
URLs work without authentication. Compilation source remains `a2f41d5`,
packaging source `7502b1f`, and release commit `677c675`.

The iPad build59 update preserved all 30 backed-up save/settings files and the
WBFS; normal launch shows both games ready to play. A command-line auto-start
attempt was rejected by the runtime's explicit no-options guard and is not
counted as gameplay evidence. The iPad was returned to normal launch.

Fifteen issue-specific replies were posted and read back after publication.
They cover recent unanswered reports/questions and cases with a concrete
reason to try the new build; unsupported GPU limits and sustained-performance
reports were explicitly kept unresolved. No issues were closed automatically.
See the [publication and outreach record](../artifacts/2026-09-20/release-050-publication.json).
