# Apple experimental build60 source and rebuild

Application compilation uses clean commit
`67c7e2f942c1226af149e6a9cc571f647528e25e`, including the maintained recursive
runtime pins. Later packaging commits do not identify different compiled code.
The embedded iOS provenance and Mac build fingerprint identify this commit.

The source delivery contains that complete core snapshot and the unchanged
verified dependency sources from the 0.5.0 source archive, SHA-256
`70f1672b99d40114807fa36eb7c12f4d161b1d5a65c13636cf2451f7291a3457`.
SOURCE-MANIFEST.json binds every member and both downloadable application
archives. No private translation, game data, saves or signing keys are supplied.

Restore the core using its `restore-source-git.py` and metadata, then follow the
Apple platform build guides with your own supported game input. This release
reused verified prepared runtimes and existing dependency/translation caches.
Incremental compilation rebuilt the changed iOS diagnostic source; the Mac main
entry point was recompiled. This was not a from-empty dependency rebuild.

The physical iOS Xcode invocation targets KartPadDual in Release with:

```
-sdk iphoneos CODE_SIGNING_ALLOWED=NO KARTPAD_DIAGNOSTIC_CANDIDATE=NO
MARKETING_VERSION=0.5.1 CURRENT_PROJECT_VERSION=60
DEBUG_INFORMATION_FORMAT=dwarf-with-dsym
```

Preserve the matching dSYM before stripping debug paths. The iOS app must contain
version 0.5.1, build60 and `KartPadDiagnosticsCandidate=NO`; run
`scripts/audit-ios-game-app.sh /absolute/path/to/KartPad.app IOS` with its default
non-diagnostic expectation. Embed fresh `write-build-provenance.py` output from
the clean compilation source and matching prepared runtime/translation.

Mac uses its pinned maintained runtime and existing Release CMake configuration:
`cmake --build BUILD --target KartPadDual --parallel 4`. Package through
`package-macos-runtime.sh` with `KARTPAD_VERSION=0.5.1` and
`KARTPAD_BUILD_NUMBER=60`; audit with `KARTPAD_EXPECTED_VERSION=0.5.1` and
`KARTPAD_EXPECTED_BUILD=60`. The Mac app is ad-hoc signed, not notarized.
The IPA is unsigned and requires the user's compatible signer.

The source packager verifies the prior archive digest and all member hashes
before retaining dependency sources. Archive snapshots, package audits and
matching symbols establish artifact identity; they do not establish an FPS gain
or a fix for the reporter's ten-minute crash. Physical affected-device acceptance
remains pending for this experimental mitigation.
